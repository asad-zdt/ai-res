# Linux setup and enforcement

Linux support uses the same feature pipeline, API contract, model bundle, and
Tkinter interface as Windows. The Linux workload definitions live in
`collector/apps_config_linux.yaml`; the Windows definitions in
`collector/apps_config.yaml` are retained unchanged. The config loader chooses
the Linux file when running on Linux.

## Python environment and tasks

Use Python 3.11 or newer. Run the Linux task dispatcher from the repository
root:

```text
python scripts/linux_tasks.py setup
python scripts/linux_tasks.py collect
python scripts/linux_tasks.py dataset
python scripts/linux_tasks.py train
python scripts/linux_tasks.py eval
python scripts/linux_tasks.py gui
```

The `api`, `test`, and `e2e` tasks are also available. The dispatcher invokes
the `.venv` interpreter directly. A Linux Tkinter package from the operating
system may be required if Tk is not included with the Python installation.
FFmpeg and curl workloads are optional on Linux and are skipped when their
executables are unavailable.

Linux collection uses `data/raw/runs_linux.csv`, separate from the Windows
`data/raw/runs.csv`, to avoid mixing platform-specific measurements. Build and
train from Linux-collected data before relying on the Linux model; processed
datasets and model artifacts are local outputs and are regenerated by the
tasks above.

## cgroups v2

CPU and memory limits are applied only when the API has access to a delegated
cgroups v2 subtree with both `cpu` and `memory` controllers enabled for child
cgroups. The engine does not write to the cgroup filesystem root or enable
controllers globally. Provision the subtree using the host's service manager
or administrator configuration, and set `AI_RES_CGROUP_ROOT` to its path
before starting the API when it is not
`/sys/fs/cgroup/ai-resource-engine`.

The configured path must exist, be writable by the API user, reside on a
cgroups v2 mount, and expose `cpu memory` in both `cgroup.controllers` and
`cgroup.subtree_control`. If these checks fail, `/run-and-compare` continues
with process niceness only and reports that CPU and memory limits were not
applied. A failure to attach a process after a cgroup has been created is
reported as an API error rather than falsely claiming successful enforcement.

The launcher holds a Linux workload behind a start gate until it has been
attached to its cgroup and its nice level has been set. This prevents the
workload from doing its initial work before the limits are in effect.

## Measurement notes

The process-tree monitor and target definitions are shared across platforms.
Network throughput is system-wide and may include unrelated processes.
`psutil` process I/O counters are used for disk throughput; their accounting
semantics can differ by platform, so measurements should be interpreted as
host-specific observations rather than directly comparable across Windows and
Linux.
